# Запросы к коллекции · занятие 1

**Предметная область:** заявки в службу технической поддержки (helpdesk)
**База и коллекция:** `helpdesk.tickets`
**Сколько документов:** 5

---

## 1. Точное совпадение строки

```js
{ status: "открыт" }
```

Найдено: **2 из 5**
Что искали: заявки со статусом «открыт» (T-1001 и T-1004).

## 2. Поле внутри вложенного объекта

```js
{ "customer.department": "Бухгалтерия" }
```

Найдено: **3 из 5**
Что искали: заявки сотрудников бухгалтерии (T-1001, T-1003, T-1004). Путь к полю внутри объекта пишется через точку и в кавычках.

## 3. Элемент массива

```js
{ tags: "сеть" }
```

Найдено: **2 из 5**
Что искали: заявки, у которых в массиве `tags` есть значение «сеть» (T-1002 и T-1004).

## 4. Оператор сравнения

```js
{ priority: { $gt: 2 } }
```

Найдено: **3 из 5**
Что искали: заявки с приоритетом строго больше 2 (T-1001 — 3, T-1002 — 4, T-1004 — 5).

## 5. Наличие поля

```js
{ assignee: { $exists: true } }
```

Найдено: **3 из 5**
Что искали: заявки, на которые уже назначен исполнитель (T-1001, T-1002, T-1004). У T-1003 и T-1005 поля `assignee` нет — форма документов отличается.

## 6. Сломанный запрос

```js
{ status: "Открыт" }
```

Что произошло: **пустой результат**

Как это видно на экране: Compass не подсвечивает запрос красным, Find нажимается, внизу счётчик `0 – 0 of 0`.

Почему так: синтаксис запроса верный, поэтому сервер его выполнил, но значения «Открыт» (с заглавной буквы) в коллекции нет — в документах хранится «открыт». MongoDB сравнивает строки с учётом регистра, поэтому совпадений ноль.

## Цена дубликата

В каждом документе заявки имя сотрудника и отдел продублированы строками (`customer.department: "Бухгалтерия"` встречается в трёх документах, `assignee: "Сидоров И."` — в двух). Если отдел переименуют (например, «Бухгалтерия» в «Финансовый отдел»), придётся обновить каждый документ с этим значением. На двухстах заявках таких документов будет несколько десятков: потребуется `updateMany({ "customer.department": "Бухгалтерия" }, { $set: { "customer.department": "Финансовый отдел" } })`. Если пропустить хотя бы один документ, в базе останутся два названия одного отдела, и фильтры начнут терять заявки.

Дубликат оставлен сознательно: заявка читается одним запросом без обращений к другой коллекции, а отдел и исполнитель на момент создания заявки — это «снимок» данных, который не обязан меняться вслед за справочником.
