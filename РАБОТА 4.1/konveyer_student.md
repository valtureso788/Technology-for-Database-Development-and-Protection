## Письмо 1. Ревью конвейеров

### 1. Выручка доставленных заказов от ноутбуков.

- Решение: есть ошибка — сумма по полю заказа после $unwind — итог повторён в каждой позиции — верно
- Комментарий: В этапе $group для подсчета выручки используется поле "$total". Скорее всего, поле total находится на уровне самого заказа и означает общую сумму всего заказа (включая другие товары, если заказ был мультитоварным).
После этапа $unwind: "$items" документ разбивается по каждому товару. Если в заказе общей стоимостью 100 000 рублей было 2 ноутбука, то после $unwind и фильтрации по категории мы получим две строки, и $sum: "$total" сложит 100 000 + 100 000 = 200 000 рублей, что неверно. Даже если ноутбук один, но с ним в заказе была мышка, $total учтет стоимость мышки.
- Исправленный конвейер:

```js
db.orders.aggregate([
  { $match: { status: "доставлен" } },
  { $unwind: "$items" },
  { $match: { "items.category": "ноутбуки" } },
  { 
    $group: { 
      _id: null, 
      revenue: { $sum: { $multiply: [ "$items.price", "$items.quantity" ] } } 
    } 
  }
])
```

### 2. Сколько заказов в пути в каждом городе.

- Решение: есть ошибка — $project перед стадией, которой нужно отброшенное поле — верно
- Комментарий: На самом первом этапе $project в конвейере явно перечисляются только два поля: number и delivery. Все остальные поля, включая status, на этом шаге отбрасываются (удаляются из промежуточного результата).
Следующим этапом идет { $match: { status: "в пути" } }. Но поскольку поля status в документах уже не существует, условие фильтрации не выполнится ни для одного заказа. Конвейер всегда будет возвращать пустой результат, из-за чего коллега и сделал ложный вывод, будто заказов в пути нет.
- Исправленный конвейер:

```js
db.orders.aggregate([
  { $match: { status: "в пути" } },
  { $group: { _id: "$delivery.city", orders: { $sum: 1 } } },
  { $sort: { _id: 1 } }
])
```

### 3. Номер первого по дате заказа каждого покупателя из трёх: c-007, c-011, c-018.

- Решение: есть ошибка — $first или $last без $sort перед $group — верно
- Комментарий: Использование оператора $first в этапе $group гарантирует получение первого документа из группы только в том случае, если перед группировкой данные были явно отсортированы.
Без предварительной сортировки (в данном случае по дате заказа) MongoDB берет документы в том порядке, в котором они хранятся на диске или возвращаются базой данных. Этот порядок не гарантирует хронологическую последовательность, поэтому результат $first: "$number" будет случайным и не обязательно вернет действительно первый по дате заказ покупателя.
- Исправленный конвейер:

```js
db.orders.aggregate([
  { $match: { customer_id: { $in: ["c-007", "c-011", "c-018"] } } },
  { $sort: { date: 1 } },
  { $group: { _id: "$customer_id", first: { $first: "$number" } } },
  { $sort: { _id: 1 } }
])
```

### 4. Пять самых дорогих доставленных заказов.

- Решение: есть ошибка — стадии стоят не в том порядке: $limit срабатывает раньше отбора — верно
- Комментарий: Коллега поставил этап { $limit: 5 } до того, как была выполнена фильтрация по статусу заказа { $match: { status: "доставлен" } }.
В результате конвейер сначала берет абсолютно любые 5 самых дорогих заказов из всей базы данных (включая заказы со статусами «в пути», «отменен», «создан»), а уже потом пытается найти среди этих пяти документов те, у которых статус равен «доставлен». Именно поэтому коллега увидел всего два заказа вместо пяти.
- Исправленный конвейер:

```js
db.orders.aggregate([
  { $match: { status: "доставлен" } },
  { $sort: { total: -1 } },
  { $limit: 5 },
  { $project: { _id: 0, number: 1, total: 1 } }
])
```

### 5. Выручка доставленных заказов по способам оплаты.

- Решение: есть ошибка — путь к полю записан без знака $ — верно
- Комментарий: В этапе группировки $group поле, по которому происходит разделение на группы (идентификатор группы _id), записано в виде обычной строки "payment.method".
В MongoDB, если вы хотите использовать значение поля из входящего документа в качестве ключа группировки, перед путем к этому полю обязательно нужно ставить знак доллара ("$payment.method").
Из-за пропущенного знака $ база данных восприняла "payment.method" как статическую текстовую строку, а не как путь к данным. В итоге абсолютно все документы попали в одну единственную группу с текстовым идентификатором "payment.method", из-за чего коллега и сделал ошибочный вывод, что способ оплаты у всех один.
- Исправленный конвейер:

```js
db.orders.aggregate([
  { $match: { status: "доставлен" } },
  { $group: { _id: "$payment.method", revenue: { $sum: "$total" } } }
])
```

### 6. Сколько штук смартфонов продано в доставленных заказах.

- Решение: есть ошибка — условие на элемент массива проверено до $unwind — проходят заказы целиком — верно
- Комментарий: На первом этапе { $match: { "items.category": "смартфоны" } } база данных отбирает только те заказы, в которых есть хотя бы один смартфон. Это правильный шаг для фильтрации самих заказов.
Однако следующим этапом идет { $unwind: "$items" }, который разворачивает массив абсолютно всех товаров из этих заказов. Если покупатель купил смартфон и чехол к нему (или ноутбук), то после $unwind чехол и ноутбук тоже превратятся в отдельные документы.
Так как после $unwind коллега не сделал повторную фильтрацию по категории, стадия $group считает сумму количества ($items.qty) для всех товаров из этих заказов, а не только для смартфонов. В результат попали лишние товары.
- Исправленный конвейер:

```js
db.orders.aggregate([
  { $match: { status: "доставлен", "items.category": "смартфоны" } },
  { $unwind: "$items" },
  { $match: { "items.category": "смартфоны" } }, // Дополнительный отбор конкретных позиций
  { $group: { _id: null, qty: { $sum: "$items.qty" } } } // Также убедитесь, что поле количества называется именно qty, а не quantity
])
```

### 7. Средний чек доставленных заказов в каждом городе, округлённый до рубля, по убыванию.

- Решение: конвейер верный — верно
- Комментарий: 1. { $match: { status: "доставлен" } } — корректно фильтрует документы, оставляя только доставленные заказы.
2. { $group: { _id: "$delivery.city", avg: { $avg: "$total" } } } — правильно использует знак $ для пути к полю города ("$delivery.city") и математический оператор $avg для вычисления среднего чека по полю "$total".
3. { $project: { avg: { $round: ["$avg", 0] } } } — использует функцию $round с параметром 0, что математически округляет полученное среднее значение до целого рубля.
4. { $sort: { avg: -1 } } — сортирует итоговые документы по вычисленному и округленному среднему чеку (avg) в порядке убывания (-1), что позволяет сразу увидеть город с самым высоким показателем на первой строчке.

### 8. Три самых продаваемых по штукам товара в доставленных заказах.

- Решение: конвейер верный — верно
- Комментарий: 1. { $match: { status: "доставлен" } } — на первом месте правильно отсекает все недоставленные заказы, чтобы учитывать только реальные продажи.
2. { $unwind: "$items" } — разбивает массивы позиций в заказах на отдельные документы. Это необходимо, чтобы работать с каждым товаром в отдельности.
3. { $group: { _id: "$items.title", qty: { $sum: "$items.qty" } } } — группирует данные по названию товара ($items.title), собирая уникальный список продуктов, и через оператор $sum корректно подсчитывает общее проданное количество штук ($items.qty).
4. { $sort: { qty: -1, _id: 1 } } — сортирует агрегированные товары по убыванию проданного количества (qty: -1). Вторичная сортировка по имени (_id: 1) гарантирует стабильный детерминированный порядок строк в случае одинакового объема продаж.
5. { $limit: 3 } — завершающим этапом ограничивает выборку, оставляя ровно три самые популярные позиции.

## Письмо 4. Свои конвейеры

### 1. Доставленные заказы по способу доставки: _id — способ (delivery.type), orders — число заказов, revenue — выручка. По убыванию revenue.

```js
db.orders.aggregate(db.orders.aggregate([
  { $match: { status: "доставлен" } },
  { 
    $group: { 
      _id: "$delivery.type", 
      orders: { $sum: 1 },

    } 
  },
  { $sort: { revenue: -1 } }
]))
```

- Результат совпадает с нужным, запусков: 1

### 2. Коллекция products. Средняя цена товаров каждой категории, округлённая до рубля: _id — категория, avg — средняя цена. По возрастанию avg.

```js
db.products.aggregate(db.products.aggregate([
  { 
    $group: { 
      _id: "$category", 
      avg: { $avg: "$price" }

  },
  { $project: { avg: { $round: ["$avg", 0] } } },
```

```js
]))
```

- Результат совпадает с нужным, запусков: 1

### 5. Одним запросом по доставленным заказам: в поле total — массив из одного документа { orders: число заказов }, в поле top — три товара с наибольшим числом штук (_id — название, qty — штуки), по убыванию qty, при равенстве — по названию.

```js
db.orders.aggregate(db.orders.aggregate([
  { $match: { status: "доставлен" } },
  {
    $facet: {
      total: [
        { $count: "orders" }
      ],
      top: [
        { $unwind: "$items" },
        { 
          $group: { 
            _id: "$items.title", 
            qty: { $sum: "$items.qty" } 
          } 
        },
        { $sort: { qty: -1, _id: 1 } },
        { $limit: 3 }
      ]
    }
  }
]))
```

- Результат совпадает с нужным, запусков: 1
